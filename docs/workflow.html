PiPER ボトル ピック＆プレイス 手順と流れ

リポジトリ piper-bottle-pp v0.1.0 ／ 1号機での立上げ 2026-10-28 ／ 別機体での再現性確認用

AgileX PiPER の手首に RGB-D カメラを付け、深度の点群だけでボトルのキャップ位置を求め、 キャップを横から挟んで2つの台の間を往復させる。制御は Jetson Orin 上の Python（pyAgxArm）だけで行い、ROS2・MoveIt・学習モデルは使わない。

1. 1号機での結果

2.2 mmハンドアイ校正のばらつき平均（最大 4.6 mm、17姿勢）
±5 mm 以内校正で推定したマーカー位置とメジャー実測の差
207 mm点群で求めたボトル高さ（実測 207 mm）
A↔B 反復台A・B間の往復を繰り返し実行し成功
項目内容
ロボットAgileX PiPER（HW H-V1.2-1、FW S-V1.8-2）、標準グリッパ AgxGripper（最大 70 mm、把持力 0〜3 N）
制御PCJetson Orin 16GB、JetPack 6.2.1（L4T R36.4.7、Ubuntu 22.04.5、カーネル 5.15.148-tegra）
カメラOrbbec Dabai DC1（USB2.0、深度 640×400、カラー 640×480 MJPG）。グリッパ側面に上下逆に取付け（eye-in-hand）
対象500 ml の不透明なボトル（満水で約 550 g）、キャップ直径 30 mm、高さ 207 mm
把持キャップ上端から 10 mm 下を、水平から 30° 下向きのグリッパで左右から挟む。力 2 N
動作観察姿勢 look で両台を撮影 → ボトルのある台からつかむ → 10 cm 持ち上げ → 反対の台へ置く → look で置き位置を確認（15 mm 以内で成功）

4. 手順

A 環境（Jetson）

1USB-CAN ドライバ（gs_usb）

bash system/build_gs_usb.sh
理由
JetPack 6 の標準カーネルに gs_usb が無い。稼働カーネルと同じ版の gs_usb.c を kernel.org から取得し、外部モジュールとしてビルドする
合格
lsmod | grep gs_usb に出る。ip -br link に can1 などが出る（can0 は本体内蔵の mttcan）
注意
入れ先は /lib/modules/$(uname -r)/updates/（drivers/net/can/usb/ は存在しない）。JetPack を更新したら再ビルド。"tainting kernel" の通知は無害

2CAN の名前と速度を固定

bash system/setup_can.sh
candump can_piper -n 20     # PiPER の電源 ON で 2A1〜2A8・251〜256 が流れる
合格
ip -details link show can_piper が ERROR-ACTIVE、bitrate 1000000。抜き差し後も自動で up
1号機
USB ポート 1-2.2:1.0。別のポートに挿したら setup_can.sh を再実行

3Python 環境

bash system/install_python.sh && source ~/.bashrc
cd ~/piper-bottle-pp && pytest -q          # 実機なしの確認
内容
venv（~/venv_pp、system-site-packages 付き）、pyAgxArm、pyorbbecsdk v1 系（main ブランチ）、piper_pp（pip install -e .）
合格
pytest が 8 件すべて pass（逆運動学、ハンドアイ計算、キャップ位置推定を合成データで確認）
注意
Dabai DC1 は OpenNI 系のため pyorbbecsdk v2 系では認識しない。v1 系を使う

実測 95 mm → tcp_z = 0.145 m。折りたたみ姿勢で表示 x 201／実測 200 mm、z 226／実測 227 mm。ベース上面が z = 0、木の台の上面 z = 21 mm

6. 押さえておく性質

性質内容と使い方
グリッパの向きJ4 = 0 のとき、J2+J3+J5 = 5° で水平、95° で真下。全関節0でグリッパは水平から 5° 上向き。逆運動学はこの関係で J5 を決め、J2・J3 を解く（J1 = atan2(y, x)）
真下向きの限界J5 の SDK 制限 ±70° のため、真下向きは TCP 高さ約 0.08 m 以下でしか成立しない。キャップ高さ（約 0.22 m）には上から届かないので、斜め 30° から挟む
姿勢角の順序SDK の [roll, pitch, yaw] は scipy の Rotation.from_euler("xyz", …)（= Rz·Ry·Rx）で一致。05_handeye.py が起動時に自己検証する
順運動学pyAgxArm の fk() は CAN 接続なしで計算できる。逆運動学とテストはこれを使うので実機と一致する
カメラ画像の向き上下逆の取付けのため表示だけ 180° 回転（camera_display_rotate_180）。計算には元画像を使う

7. 起きた問題と対処

現象原因対処
USB-CAN を挿しても CAN が出ないJetPack 6 に gs_usb が無いsystem/build_gs_usb.sh でビルド（updates/ に入れる）
J6 が −117° で stall・過電流、以降の指令が通らないJ6 原点が約 −288.6° ずれていた。SDK 表示は範囲外で固着CAN 生データで範囲を測り、中心で calibrate_joint(6)、clear_joint_error(6)
傾けると TCP 高さが表示と 44 mm 違うSDK のフランジ点は取付け面より約 50 mm 手首側tcp_z = ノギス実測 + 50 mm
真下向きの直線移動がタイムアウトJ5 が制限 70° に到達J5 に余裕のある姿勢で作り直す。把持は斜めから
カメラが開けない（res-6）ライブ表示など別プロセスが使用中他のカメラスクリプトを閉じる
置き面の高さを誤判定（193／177 mm）浅い角度で見る面は点がまばらsurface_z を固定値で与える
キャップ上端が +6 mm 高いほぼ水平に見ると輪郭に背景との混合画素が出るlook を見下ろす向きに変更
キャップ中心が手前に寄るキャップの手前半分しか見えない半径 15 mm の円を当てはめる
台Bで爪が浅く失敗台の位置により把持点の奥行きが不足--set-advance B で放射方向に前進補正
保存姿勢 down が誤った値で上書き未特定（同名で保存した可能性）保存名を確認してから s。go の前に p で確認
